# 发布文案

> **来源声明：本包里每一份文档都是 AI 写的**，包括本文以及
> `LIMITATIONS.md`、`PITFALLS.md`、`BUILD_SPEC_FOR_AGENTS.md`、
> `DISTRIBUTION.md`。它们跨多轮会话产出，依据是设备日志、源码，以及在源码上
> 实际跑过的命令。数字能追溯到日志或可重跑的命令；**解读不是第一手的**——没有
> 任何 AI 在设备上装过它。如果你想自己写一版发布文案，事实基础是上游
> [`repentogxm`](https://github.com/0xl0cal/repentogxm) 加上
> `BUILD_SPEC_FOR_AGENTS.md`。

发布本项目时可直接复制粘贴的文字。这里没有任何构建输入；它存在的理由是
让发布的人不必从头重写措辞 —— 同时也让措辞对「这是什么、不是什么」保持
诚实。

本目录中的这个文件通篇是中文；对应的英文版在上一级的
`ANNOUNCEMENT.md`。改动任意一边时请让两边保持同步：里面的
事实必须一致，只有语言应当不同。

每个版本都刻意写明三件事，因为它们是最先被问到的三个问题：

1. **没有 APK，也没有 `.so`。** 只发源码，这是有意的。
2. **只测过一台设备。** 帧数不是普遍结论。
3. **两个已知缺陷没有修。** 在别人自己撞上之前先说清楚。

后来按作者要求加了第四条：**说清楚哪些文档是 AI 写的**，并给不放心的人一条
替代路径（用上游规格自己编）。

## 0. 标题

**不要写 "How to port"。** 这个包是一个已经做完又放弃的移植加上它的记录，不是
教程。标题长得像教程，第一条回复必然是"教程在哪"。论坛有标签就用标签，游戏名要
写全——没人会去搜 "Tboi"。

```
[Development Documents] The Binding of Isaac Repentance — x86 PC to arm64 Android port
```

论坛标题上限接近 60 字符时的短版：

```
[Docs] The Binding of Isaac: Repentance — x86 PC to arm64 Android
```

## 4. 发帖须知

- **别贴表格。** README 里的对照表在 Discord 和多数论坛主题下会渲染成一片
  竖线，所以上面各段都用加粗标签和 `·` 分隔，而不是表格。
- **「没有 APK」放前三行。** 人只扫开头；如果第一眼看到的是帧数，回复一定
  是「APK 在哪」。
- **给链接，别搬运。** 归档或仓库地址附在主条末尾。不要把 `PITFALLS.md` 的
  内容贴进帖子——那份文档的意义就在于让人自己去读。
- **Discord 上把楼层理清。** 主条发展示频道，技术追问转帮助频道，别让几十
  条问答压在公告底下滚走。
- **EULA 那个问题一定会来，照直答。** 「可能违反，风险自负，先读
  `DISCLAIMER.md`」就是诚实答案，也能干净地结束话题。不要把它说软。
- **不要承诺修复。** 两个缺陷已明确记录为未解决；说「正在弄」等于凭空造出
  一个并不存在的承诺。
